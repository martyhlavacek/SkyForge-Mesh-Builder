# Cost Architecture — Mesh Builder Sidecar v0.5.2

## Scope

This architecture governs only OpenAI image generation for the accepted beauty → authority → mesh workflow. It does not introduce Meshy, Hunyuan, multiview generation, or geometry changes.

## Transaction boundary

```text
validate complete request
  → resolve strict governed prompt
  → calculate official fail-closed output estimate
  → require confirmation when threshold is exceeded
  → calculate deterministic request digest
  → acquire in-process digest lock
  → completed cache lookup
  → deny unresolved/possibly-charged duplicate
  → atomically reserve spend and enforce budgets
  → perform one HTTP call
  → capture request ID and usage
  → reconcile output/input token cost when usage supports it
  → atomically commit content-addressed cache
  → create the human-facing concept-run directory
```

No concept-run directory is allocated before validation, budget reservation, transport, reconciliation, and cache handling complete. A budget or pricing rejection therefore cannot leave a partial concept run.

## Fail-closed gates

Transport is not called when:

- the model/quality/size cell is absent from governed pricing;
- candidate count is invalid;
- the confirmation threshold is crossed without confirmation;
- per-request, per-asset, or per-session budget would be exceeded;
- the ledger cannot be read or atomically written;
- an identical digest is already reserved, possibly charged, or reconciled without a durable cache.

## Spend accounting

The ledger records:

- reservation ID and deterministic request digest;
- session and asset IDs;
- stage, model, quality, size, candidate count;
- estimated output cost and lower-bound flag;
- pricing date and source;
- attempt count;
- actual OpenAI usage;
- calculated actual output/input cost and calculation basis;
- request ID;
- cache state;
- reconciliation state;
- cumulative asset and session spend.

Atomic writes use a same-directory temporary file, flush, `fsync`, and replace. Failure to commit denies the request before transport. A timeout or connection loss after dispatch becomes `possibly_charged`; the reservation remains counted.

## Actual-cost hierarchy

1. When response output-token usage exists, output cost uses the official model image-output token rate.
2. Detailed text/image input tokens are added using official model rates.
3. When output usage is absent, returned-image count uses the governed output-image table and the record remains explicitly lower-bound.
4. Unknown rates are never guessed.

Authority edits are displayed pre-call as output-only lower bounds because reference-image input token use is unknown until actual usage arrives.

## Digest and cache

Canonical digest input:

```json
{
  "model": "…",
  "quality": "…",
  "size": "…",
  "candidateCount": 1,
  "resolvedPrompt": "…",
  "referenceImageSha256": "… or null"
}
```

The canonical JSON is UTF-8, sorted by key, compact, then SHA-256 hashed. Cache entries are stored by digest and contain generated bytes, per-image SHA-256, MIME type, usage, request ID, and non-secret settings. They do not contain API keys, Authorization headers, or raw HTTP request bodies.

A valid identical completed request returns cached bytes and writes a zero-cost cache-hit ledger entry. A deleted, incomplete, unreadable, or corrupted cache paired with a prior reconciled digest fails closed and cannot trigger another paid dispatch. If a billed response cannot be durably cached, the ledger marks `reconciled_cache_unavailable`, counts actual cost, and blocks identical resubmission.

## Retry policy

v0.5.2 performs no automatic paid retry. This is intentionally stricter than Claude’s broader 429/5xx recommendation because the provider does not document an Images API idempotency header and an ambiguous billed attempt must not be repeated automatically.
