# v0.8.1 Meshy Live-Smoke Preauthorization Handoff

No Meshy smoke call is authorized. Do not enter or use an API key, submit or poll a provider task, download provider artifacts, consume or purchase credits, or begin provider-result visual testing under this handoff.

The accepted no-spend integration deliberately has an empty production artifact-host set and no production resolver. The download path is therefore intentionally inoperable. Before Marty can separately authorize one geometry-only task, all of the following must be completed and recorded against the exact candidate:

1. Re-verify the official Meshy Multi-Image endpoint and every request parameter.
2. Re-verify that `meshy-6` remains available for the intended operation.
3. Re-verify the current credit cost.
4. Re-verify provider retention rules.
5. Identify the actual official Meshy asset-serving hostnames without inference or speculative broadening.
6. Configure only that exact approved-host set.
7. Configure a real DNS/address resolver for the production artifact-host policy.
8. Prove production remains fail-closed for every other hostname, non-public address, unsafe redirect, and mutated final response URL.
9. Prepare one exact approved top/front/right authority bundle and its redacted request preview.
10. Obtain separate explicit Marty authorization for a single geometry-only task with a maximum 20-credit cap.

Completing these prerequisites does not itself authorize the task. The authorization must bind the exact bundle digest, verified provider contract, exact approved-host configuration, resolver configuration, request preview, and credit cap. A second task requires separate authorization.

MBS-182 remains open as an Observation. MBS-183 remains open as this mandatory pre-smoke contract-verification requirement. MBS-136 remains open against a real provider. No tag, release, user testing, second provider, or Alpha 2 work is included.
