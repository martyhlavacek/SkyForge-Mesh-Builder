# v0.8.1 MBS-214 / MBS-215 route-guard status

This focused candidate adds transactional route guards without changing the canonical lifecycle, authorization path, provider path, contract evidence, or cost governance.

## MBS-214

`POST /bundle/import` now verifies the selected runtime against the versioned active Track S session identity before reading uploaded files. An active isolated Track S session refuses the legacy multiview import route with HTTP 409. The refusal occurs before authority files are written, a bundle is created, `inputKind` changes, TaskLog events are appended, or approval/provider state can change. Legitimate non-session multiview workflows remain supported, and the historical MBS-195 workspace remains read-only.

## MBS-215

`POST /artifact/preflight` now refuses historical/read-only runs with HTTP 409 before calling `PilotRuntime.preflight()`.

Static inspection of the active preflight implementation found:

- `PilotRuntime.preflight()` calls `preflight_artifact_url()` and only transforms keys in the returned in-memory report.
- URL policy inspection invokes the configured address resolver. The production resolver calls `socket.getaddrinfo()`, so an active preflight can perform operating-system DNS resolution.
- With no transport argument, preflight performs no HTTP request after policy inspection.
- With a transport argument, it may issue bounded HEAD requests and validate every redirect and final response URL. The transport implementation may open network sockets.
- The implementation does not write evidence, modify runtime state, append TaskLog events, or mutate workspace files.
- The historical route guard prevents entry into all of those preflight operations, including DNS and transport calls.

All live-network use remains outside this task. Tests use spies and disabled transport only.

## Evidence preservation

The approved human Track S run remains at `BUNDLE_APPROVED` for the exact `single_view_v1` digest. Its beauty image, input record, approval, TaskLog, session identity, and active-session pointer are compared byte-for-byte before and after the remediation. Historical MBS-195 evidence receives the same before/after comparison.

MBS-213 remains closed. MBS-214 and MBS-215 remain candidate-remediated pending independent review. The contract remains stale, failed-task charging remains `UNRESOLVED`, and no provider operation is authorized.
