# v0.8.1 Multiview Meshy Pilot UI — No-Spend Implementation

The pilot is a separate Flask application and process at `http://127.0.0.1:5180`. The unchanged v0.7.1 application remains at `http://127.0.0.1:5179`. The pilot launcher is `mesh-builder/scripts/run_pilot_ui.command`.

The interface is titled **SkyForge Mesh Builder — v0.8.1 Multiview Meshy Pilot** and is visibly labelled **EXPERIMENTAL PILOT — SEPARATE FROM v0.7.1 PRODUCTION ROUTE**. It imports prepared PNG/JPG/JPEG files only. It does not generate, edit, infer, or fabricate authority views and never asks for an API key.

## Canonical lifecycle

`TaskLog.append()` is the only lifecycle authority:

```text
None → PREPARED → BUNDLE_APPROVED → CONTRACT_REVERIFIED
→ AUTHORIZATION_PREVIEWED → COST_APPROVED → SUBMITTING
→ SUBMITTED → POLLING → POLLING | SUCCEEDED | FAILED | CANCELED
SUCCEEDED → DOWNLOADED → VALIDATED → USER_ACCEPTED | USER_REJECTED
```

`SUBMITTING → FAILED` is also permitted. `FAILED`, `CANCELED`, `USER_ACCEPTED`, and `USER_REJECTED` are terminal. The UI exposes no cancellation action and projects the backend log read-only.

## Authorization and freshness

Authorization schema `skyforge.meshy-pilot-authorization.v1` uses the accepted `rfc8785==0.1.4` canonicalizer, prohibits floating-point values, omits absent optional fields, and binds every field required by MBS-188. The fixed request is Meshy-6, geometry-only GLB, with both estimate and maximum fixed at 20 credits.

The pilot reads `docs/contracts/MESHY_CONTRACT_REVERIFICATION_2026-08-04.md` and derives its SHA-256 and verification date from those committed bytes. The freshness window is 24 hours. The snapshot is expected to display `STALE`; the pilot cannot manufacture freshness and refuses `CONTRACT_REVERIFIED`, `AUTHORIZATION_PREVIEWED`, `COST_APPROVED`, and submission while stale.

## Bundle and provider boundaries

Exactly three independently stored views are required in `top`, `front`, `right` order. The UI shows filename, SHA-256, dimensions, mode, and provenance. Duplicate bytes, fixture-to-authority promotion, single-view substitution, unsupported profiles, and post-approval mutation fail closed. After approval, discard-and-restart is the only recovery.

The pilot reuses `MeshyMultiImageProvider` with `SubmissionAuthorization`, its duplicate-spend reservation, host/DNS/redirect policy, network kill switches, and controlled download path. It has no second provider transport implementation. Polling is fixed at 10 seconds and 30 attempts, redirects at four, and a mocked `SUCCEEDED` result proceeds immediately to controlled capture. Provider `expires_at` is projected as an absolute timestamp.

## No-spend status

This implementation and its evidence are offline. No API key was entered, read, or used; no provider task was submitted or polled; no artifact was downloaded; no credits were purchased or consumed; no authority image was generated; no human-approved three-view bundle was claimed; fixtures are not Meshy outputs; and no live operation or user testing is authorized.

MBS-185 through MBS-190 are implemented for independent review. MBS-191 is handled with backend spelling `CANCELED` as a provider-returned terminal state, without exposing a cancellation control. Future reviewer findings begin at MBS-192.
