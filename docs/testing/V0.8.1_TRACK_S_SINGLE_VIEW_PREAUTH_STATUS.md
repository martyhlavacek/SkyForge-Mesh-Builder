# v0.8.1 Track S single-view preauthorization status

This branch implements offline preauthorization architecture only. It does not authorize or perform a Meshy task.

Track S uses the existing canonical TaskLog lifecycle, authorization path, spend-governance path, `MeshyMultiImageProvider`, and `/openapi/v1/multi-image-to-3d` endpoint. It adds `SingleViewReconstructionInputV1` beside the unchanged strict `MultiviewAuthorityBundleV1`, selected through the common `inputKind` values `single_view_v1` and `multiview_bundle_v1`. The provider request for the first Track S experiment would contain exactly one approved three-quarter beauty reference. The approved TOP authority is bound separately as a validation target and is not reconstruction input.

The committed Track S policy freezes the measurement specification, deterministic 1024 × 1024 top-silhouette alignment, exploratory IoU interpretation bands, 64 × 64 / 75° gameplay-camera evidence, hard geometry gates, experiment decisions, fixed Meshy request, 20-credit first-task ceiling, zero automatic retries, and no automatic second task. The production IoU floor remains 0.94.

Live progression is intentionally blocked because:

- the retained Meshy contract snapshot is stale under the 24-hour rule;
- failed/rejected-task charging remains `UNRESOLVED`;
- no real run-specific preregistration bound to a final approved beauty reference has been committed;
- no live authorization has been separately granted.

The rejected MBS-195 FRONT and RIGHT hashes are quarantined from new reconstruction inputs at construction, approval, authorization, and provider-request boundaries. Their preserved workspace remains readable as historical evidence. MBS-195 remains open, as do MBS-136, MBS-208, and MBS-209.

`ABORT_MESHY` is an experiment decision, not a provider lifecycle state. No experiment decision submits or authorizes another task. `ESCALATE_TWO_VIEW_ELIGIBLE` permits only consideration of a separately authorized future experiment.

No API key, provider transport, contract freshening, authority-view fabrication, credit use, tag, release, merge, or human UI testing is part of this implementation record.
