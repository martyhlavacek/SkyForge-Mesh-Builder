# v0.8.0 Multivolume Alpha 1 Architecture

Alpha 1 is an offline, opt-in experiment alongside the unchanged v0.7.1 authority-mesh generator. It is not imported by the server, UI, provider registry, VMP exporter, or Import Probe.

The experiment first invokes `generate_authority_mesh()` in an external evidence directory. Its passing GLB becomes the exact planform-bearing `base_shell`. Authority images provide silhouette extents and occupied-row-span constraints. Schema-validated profile recipes provide semantic identities and approximate normalized positions, and deterministic closed `trimesh` primitives are fitted within those constraints. Alpha 1 does not detect cockpit, engine, weapon, or belly features directly from pixels. Row-span fitting constrains placement but does not infer semantic landmarks. RGB is not read for placement or dimensions; it is used only for planar texture projection.

Each semantic component remains an independently watertight shell. The declared penetration is an input only: gates use measured embedded and exposed vertex fractions against the local two-sided base-shell envelope, plus protrusion and nearest-shell distance. Alpha 1 deliberately avoids boolean union and new geometry dependencies. The assembly is exported with the established target-XYZ to glTF-X/Z/-Y encoding and independently reloaded to audit component count, names, bounds, topology, semantic registry, and measured peak-height clusters. Top-silhouette preservation uses assembled-minus-base IoU with a maximum 0.005 degradation; attachment and semantic-height gates—not absolute assembled IoU—provide component-placement evidence.

Supported recipes are `enemy_gunship` and `enemy_interceptor`. Unsupported profiles and recipes missing the required shell, body, or semantic-peak height groups fail closed with deterministic validation errors. Outputs include textured and component-coloured GLBs, OBJ, reports, registries, pre-export and independently reloaded topology records, measured IoU/height/attachment data, diagnostic views, and SHA-256 manifests.

This architecture only candidate-addresses MBS-151 through MBS-154. It does not close findings, change the accepted generator, or authorize VMP/UI/provider integration or user testing.
