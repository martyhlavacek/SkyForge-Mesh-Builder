# v0.8.1 Paid-Call Security Contract

The pilot defaults to no-spend dry-run operation. Provider POST is denied unless every control below passes at the transport boundary:

- local paid-provider enablement;
- exact current approved bundle digest;
- digest-bound explicit confirmation;
- supported profile;
- current estimated credits at or below the explicit maximum;
- secure API-key availability;
- absence of `CI`, `GITHUB_ACTIONS`, and the `SKYFORGE_PROVIDER_NETWORK_DISABLED=1` kill switch;
- no prior task ID and no earlier or ambiguous submission attempt.

The key must come from secure runtime handling and must never appear in arguments, JSON evidence, logs, exceptions, manifests, or archives. An ambiguous POST permanently blocks automatic resubmission. Polling retries may issue GET requests only. HTTP 400, 401, 402, and 429 fail closed.

`CI`, `GITHUB_ACTIONS`, and `SKYFORGE_PROVIDER_NETWORK_DISABLED=1` are enforced by one provider-layer guard before submission, task retrieval, polling, single-artifact download, and bulk download. Artifact URLs, resolved addresses, and every redirect target must pass the versioned exact-host policy before transport; the final response URL is checked again before bytes are accepted.

The submission reservation is deliberately created before request construction and remains held after ambiguous failure. This is safe-direction behavior. Manual recovery requires an operator to independently prove that no provider task was created and obtain separate authorization before removing the exact digest reservation; no automatic clearing or recovery tooling is part of this candidate (MBS-182).

This candidate authorizes zero paid calls. Official Meshy endpoint, pricing, retention, and parameter assumptions are time-sensitive and must be independently re-verified before any later live authorization.
